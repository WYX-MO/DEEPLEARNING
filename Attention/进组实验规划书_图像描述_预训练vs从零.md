## 1. 背景与动机（先讲清楚"为什么这个问题值得做"）

图像描述（Image Captioning）= 输入一张图，输出一句自然语言描述。主流做法是"编码器-解码器"：

```
图片 → 视觉编码器(ViT/CNN) → 特征 → cross-attention decoder → 描述文字
```

**业界事实**：几乎没有人在 6k 张图上从零训视觉编码器。几乎所有可用的图像特征（VGG/ResNet/CLIP）都来自 **ImageNet 级别（百万张）的预训练**，这是一个"常识"，但很少有人亲手验证过**"如果偏不这么做、从小数据端到端硬训，到底会发生什么、差在哪、差多少"**。

**我做这个项目的价值 = 亲手把这条"常识"从'听说的'变成'量化的、可解释的'。**

前一轮 100 epoch 的实验已经给出一个明确而反常的现象（详见 §3 现状），它构成了本规划的起点。

## 2. 研究问题与假设

### 2.1 核心科学问题

> **当训练数据远小于预训练数据规模时，端到端从零训练的图像编码器为什么学不到可用的视觉表示？预训练（冻结 / 微调）能把表示"喂"到多好？两者差距的可量化来源是什么？**

### 2.2 分解为可证伪的假设

- **H1（已初步证实）**：在 Flickr8k（6k 图）上端到端从零训 ViT+decoder，视觉编码器基本学不到图像内容，输出主要由**语言先验**主导。
  - 证伪方式：若 H1 假，则"去掉图像（全零图）"与"真实图像"的生成差异应很大。实测差异仅 +3pt（见 §3），H1 成立。
- **H2（待验证）**：用 ImageNet 预训练 ViT 初始化（无论冻结还是微调），图像条件化显著增强——表现为 image_gain 上升、BLEU 上升、对**稀有/具体名词**的正确描述能力上升。
- **H3（研究张力，待数据裁决）**：在 6k 这种极小数据下，**冻结预训练特征 vs 端到端微调预训练 ViT** 谁更好？
  - 直觉方向 A：冻结更稳（86M 参数全量微调在小数据上易过拟合）→ 期望 **冻结 ≥ 微调**。
  - 直觉方向 B：微调能让特征适配 Flickr8k 风格，图像增益更高 → 期望 **微调 ≥ 冻结**。
  - **这个不预设答案、用实验裁决的问题，恰恰是进组面试里最有价值的谈资。**

## 3. 现状与初步结果（前一轮实验，作为 baseline 锚点）

已完成的配置（作为实验 A / 从零端到端）：
- 编码器：自写 12 层 ViT（d_model=192，patch=14，输入 224×224 → 16×16 图块）
- 解码器：3 层 cross-attention decoder（teacher forcing + 自回归 greedy decode）
- 训练：AdamW lr=1e-4，StepLR，100 epoch，batch=64，`CrossEntropyLoss(ignore_index=0)`（`<pad>=0`）

| 指标 | 数值 | 说明 |
|---|---|---|
| greedy BLEU-1/2/3/4（200 张 test） | 51.2 / 27.3 / 14.5 / 9.1 | 模型逐图生成的分数 |
| **"逐图生成" 能超过"每张图复读同一句"吗** | BLEU-1：51.2 **<** 52.0 | **不能**（BLEU-2/3/4 略高，说明有一点点图像信息） |
| 全零图 greedy decode | 6 张全输出 `a man is standing on a beach .` | 确定性坍缩到一句"万能模板" |
| token acc：真实图 vs 全零图（teacher forcing） | 39.2% vs 36.2% → **image_gain +3.0pt** | 图像只带来 +3pt，视觉极弱 |
| 纯语言基线：永远猜 `a` | token acc 12.2% | 语言先验的下界参照 |

**三个可写进简历的量化结论：**
1. 模型**语法流畅但视觉空泛**：能复读模板，猜不对具体动作/颜色/场景（kiss→"standing on sidewalk"、攀岩→"swing"）。
2. **BLEU-1 严重虚高**：一句"万能默认句"在所有 test 图上的 BLEU-1(52.0) 就追平了模型(51.2)——任何只报 BLEU-1 的工作都会被高估。
3. 我用"**零图坍缩句 + 默认句对照基线**"这一个探针，就定位出"模型在背语言先验"——这是一个低成本、可复现的诊断方法。

## 4. 实验设计（核心：受控对比）

### 4.1 总览：四组对照臂

| 臂 | 编码器 | 是否冻结 | 解码器 | 一句话目的 |
|---|---|---|---|---|
| **A** 从零端到端 | 自写 ViT(12L,d192) 从零随机初始化 | 训 | 3L 从零训 | 基线（已完成） |
| **B** 冻结预训练 | ImageNet 预训练 ViT-B/16(768d) | **冻结** | 3L 重训 + 新投影 | 回答"预训练特征 + 只学对齐"能到多好 |
| **C** 预训练+微调 | 同上 | **全量微调** | 3L 一起微调 | 裁决 H3：6k 图上微调是帮还是害 |
| **D**(可选) 经典 CNN | ImageNet 预训练 ResNet50(2048d) | 冻结 | 3L 重训 | 经典对照；顺带看 ViT vs CNN 预训练特征 |

> 为什么这么设计：**一次只换一个变量**。A/B 只差"编码器有没有预训练"；B/C 只差"是否微调"。这样任何指标差异都能归因，不会被"顺手改了好几个地方"污染。

### 4.2 每个臂必须锁死的超参（可复现性）

- 同一种子（训练、采样、固定 BLEU 评估子集）；headline 数字跑 3 个种子取 mean±std（标注成本）。
- 同一评估子集（固定 200 张）每 epoch 快照 greedy BLEU；里程碑处跑全 test。
- 用 dev 选模型（early stop / 选最优 BLEU），test 只报一次——避免用 test 反复调参导致虚高。
- 每臂保存命名：`exp{ARM}_{model}_e{epoch}.pth`，与旧 `vit_model_epoch_*` 彻底隔离。

### 4.3 编码器接入方式（关键实现点，先讲清原因）

- 维度桥接：B/C 需在解码器前加一层**新随机初始化的投影** `Linear(768→192)+LayerNorm`；D 用 `Linear(2048→192)` 并把 7×7 空间拉平成 49 个 token。**原因**：现有 cross-attention 的 K/V 是 192 维，预训练特征维度不同，必须桥接；这一层属于"该训的新参数"。
- **归一化陷阱**：预训练 ViT/ResNet 吃 ImageNet 的 mean/std（0.485/0.456/0.406），而不是现在用的 0.5。**原因**：归一化错，特征直接废。B/C/D 的 data pipeline 必须换成对应统计量。
- 取"空间 patch token"而非仅 CLS：用 torchvision 的 feature-extraction API 取 `[B, 197, 768]` 的 token 序列（含 cls 或不含均可在实现里定）。**原因**：captioning 的 cross-attention 需要"图里哪里有什么"的空间信息，单向量不足以支撑注意力学习。
- C 臂微调时替换/丢弃分类头，保留 transformer 主体权重初始化。

### 4.4 评估协议（防止"看着 acc 高就以为成功了"）

1. **主指标**：greedy decode 的 BLEU-1/2/3/4（+ 可选 CIDEr）。不是 teacher-forcing token acc。
2. **图像条件化探针（我最看重的可解释指标）**：同一批图，真实 vs 全零，teacher-forcing token acc 差 = `image_gain`。
   - 期望：A≈+3 → B/C 应显著更高。若 B/C 后 image_gain 仍 ≤5，说明问题不在初始化，需另找原因（这本身就是结论）。
3. **默认句基线**：全程复读 `a man is standing on a beach .` 的 BLEU 作为"无视觉下界"，模型必须明显跑赢它才算视觉有效。
4. **稀有名词命中率**：只统计测试标注里出现频率低的**具体词**（如 breed、sofa、kayak），看模型能否答对。**原因**：虚词/模板词被语言先验白送，只有稀有实体词才逼着模型真看图。
5. **注意力可视化**：解码第 t 个词时，cross-attention 权重映射回图。对正确生成的实体词，理想注意力应聚焦到对应物体区域。做成图，既是验证也是简历配图。

### 4.5 进阶消融（时间允许再上，标注"研究增量"）

- **训练信号增强**：把 Flickr8k 每图 5 句标注**全部用上**（现在每 epoch 只随机抽 1 句），等效 5× 数据。
- **Scheduled sampling**：训练中按概率喂模型自己的预测，抗 exposure bias（前面已证 teacher forcing 虚高）。
- **Label smoothing（0.1）**：压模板词的过度自信。
- 理由：这些改动要**单独成臂**、单独归因，不能和 A/B/C 混在一起。

## 5. 技术路线与里程碑

| 阶段 | 内容 | 交付 | 预估成本 | 原因备注 |
|---|---|---|---|---|
| P0 基建 | 把训练脚本参数化（arm / backbone / seed / 归一化开关）；写统一评估脚本 `eval_caption.py`（BLEU+image_gain+默认句+稀有词+出图） | 可复现入口 | 1~2 天 | 没有统一评估，后面每个臂各说各话 |
| P1 锚点 | 复跑 A 短程，核对与 epoch100 结论一致 | 复现数字 | 0.5 天 | 防止基建改动污染已有结论 |
| P2 臂 B（冻结） | 接入预训练 ViT + 投影，重训 decoder | B 全套指标 | 1~2 天（含调参） | 最便宜、最可能直接看到 image_gain 跳升 |
| P3 臂 C（微调） | 低 lr + warmup 微调全模型 | C 全套指标 | 2~3 天 | 裁决 H3；注意防过拟合 |
| P4 臂 D（可选） | ResNet50 冻结对照 | D 指标 | 0.5~1 天 | CNN vs ViT 预训练特征对比 |
| P5 进阶消融 | 数据 5× / scheduled sampling / label smoothing | 归因表 | 2~3 天 | 每一项单独成臂 |
| P6 写作 | 图表、结果表、叙事、代码整理 | 2~4 页报告 + repo | 2 天 | 输出物才是简历本体 |

> 单卡预算合计约 1~2 周（非满负荷）。每一步都"小而可逆"：先 P0/P2 用半天看到 image_gain 有没有起色，再决定是否投入 P3/P5 的大算力。

## 6. 为什么"不自训 ImageNet 预训练"（主动说明，展示成熟度）

很多人第一反应是"那我干脆自己训一个 ImageNet 分类器"。规划里**明确排除**，理由量化如下：

- ViT-S/16 到 ImageNet top-1 ~80% 需约 **300 epoch、8×V100 约 2~3 天**；
- 折算到单卡 RTX4060（约 1/10 吞吐）→ **3~4 周以上**；
- 且据 ViT 原文，仅 ImageNet-1k 上从零 ViT **未必超过同算力 ResNet**——即花几周只为了追平。
- 结论：**预算应该花在"评估与归因"而不是"重复造 ImageNet"**。这恰恰是预训练生态（torchvision/timm `weights=` 一行加载）存在的意义。

把"我算过账、知道自训 ImageNet 不划算、选择用受控实验验证预训练价值"写进方法论，比任何代码都更能体现科研判断力。

## 7. 风险与备选方案

| 风险 | 影响 | 缓解 / 备选 |
|---|---|---|
| 全量微调 ViT-B/16（86M）在 6k 图上过拟合 | C 臂结论被污染 | 低 lr + 长 warmup + early stop；若仍崩，退化为"冻结 + 只微调 decoder"并如实报告 |
| 显存不足（8GB） | 训练中断 | batch 调 16~32 + 梯度累积；先跑通再放大 |
| B/C 的 image_gain 仍不高 | 原假设动摇 | 这是**有效结论**不是失败：转向检查 data pipeline / 归一化 / 投影层是否接对（先用小样本人工核对注意力） |
| 结果波动大 | 结论不稳 | 固定种子 + 固定评估子集 + 3 种子 mean±std |
| 编码器接入 bug 没发现 | 全盘假象 | P2 第一步先做**单样本人工核对**：喂 1 张狗图，看解码词和 attention 热区是否在狗身上 |

## 9. 附录：这份实验在简历 / 面试里怎么讲

### 9.1 一段话研究叙事（可直接放 CV 的 project 栏）

> 在 Flickr8k 图像描述任务上，我从零实现了 ViT + cross-attention 解码器，并用端到端训练得到 100-epoch 基线。通过自建"全零图消融 + 默认句对照"的诊断方法，我定量证明该基线约 51 BLEU-1 中有 52 分来自纯语言先验（图像仅贡献 +3pt 的 token 精度）——即小数据从零训练难以习得视觉表示。据此设计了 冻结/微调 ImageNet 预训练 ViT 的受控对照实验，用于裁决"小数据下冻结与微调谁更优"，并配套 BLEU、image_gain、稀有名词命中率与注意力可视化评估协议。

### 9.2 技能标签（按"我真正做过"来列）

- PyTorch；Transformer：self/cross-attention、causal mask；ViT 从零实现与训练
- 训练范式：teacher forcing / greedy decoding / exposure bias
- 指标设计：BLEU、image_gain、默认句基线、稀有词命中率
- 实验方法：受控对照、可复现、失败诊断、单卡算力预算

### 9.3 面试高频问答的"弹药"

- **"你怎么知道你的模型没在学图像？"** → 零图坍缩 + image_gain +3pt + "逐图生成 ≈ 复读默认句"。
- **"BLEU-1 51 分高吗？"** → 不高，因为默认句就 52；只有 BLEU-4 和稀有词命中率才算数。
- **"为什么从零训学不动？"** → ViT 缺 CNN 的归纳偏置，需靠数据补；6k 图付不起学费；且 caption loss 被虚词主导，视觉梯度稀薄。
- **"下一步怎么做？"** → 换预训练做对照、5 句标注全用、scheduled sampling，并用 image_gain 判断每一处改动是否真的让模型"更看图"。

### 9.4 进组后可能的延伸

- 换 COCO（118k 图）检验"数据规模 crossover"：数据多大时从零端到端能反超冻结特征。
- 对比自监督（MAE/DINO）特征 vs 有监督特征。
- 把"image_gain/默认句"诊断推广成一个小工具/小论文的方法学贡献。
